When to use this reference

Use this eight-stage pipeline when starting from an identified examination question to produce a faithful Core2 reader and traceable learning routes. For a syllabus-driven chapter without an authenticated source question, use the curriculum-first Core1A/Core1B Field Guide without fabricating Core2 source admission.

Auditing is separate: the Independent Audit Field Guide defines R00/R01 evidence review, science falsification, first-attempt integrity, quality decisions and one-time Golden Sample governance. This process map cannot independently award academic approval. Redistribution-rights questions are outside this educational quality protocol.

Stage-by-Stage Reference, Templates & Benchmarks

Stage 1 · Question Intake, Source Custody & Fingerprinting

Stage 01

Segregate question items into Git-excluded custody (workspace/sources/<topic>/). Decompose each item into 3 independent files: stem text, diagram/raster, and official answer key. Calculate SHA-256 byte hashes and mint unique stable IDs.

Tools & Templates Used: templates/skills/smart-labelling-1/scripts/check_sl1.py templates/core2-exam-card/TEMPLATE-intake.json schemas/v1/source.schema.json

Measurable Pass Benchmark Exact 64-character SHA-256 cryptographic match between file bytes and metadata record (`declared_matches_observed: true` across 100% of candidate items). Zero duplicate IDs across the entire repository (cross-topic and cross-year disambiguation, e.g. NSEJS-2019-P-OPT-Q01/Q02 vs NSEJS-2019-P-ELEC-Q01/Q14). Clear separation between EXAM_PAPER vs TEXTBOOK vs AUTHORED_TRANSFER.
Strict Falsifier / Failure Trigger Modifying a single character in the question stem, swapping an image locator, substituting a redrawn diagram without flagging as DERIVED_FIGURE, or collision between historical IDs immediately trips HASH_MISMATCH / INTEGRITY_FAIL.

Stage 2 · Cognitive Demand Profiling (SL1 ➔ Optional P1 ➔ SL2)

Stage 02

Trace the shortest valid solution route. Identify the decisive mental move. Score the 5 intrinsic complexity dimensions on a 0–2 scale. If real unassisted student attempt data exists, record P1; otherwise, explicitly set P1 to NOT_APPLICABLE (never fake student attempt history).

Tools & Templates Used: templates/skills/smart-labelling-2/scripts/check_sl2.py src/grade9qa/demand.py schemas/v1/assessment.schema.json

Measurable Pass Benchmark Every factor $c_i \in \{0, 1, 2\}$, total score $\sum c_i = \text{difficulty.score} \in [0, 10]$. Strict D-Band alignment: D1 (0–2), D2 (3–5), D3 (6–7), D4 (8–10). Zero empty factor evidence fields. Proposed status strictly marked PROPOSED / UNREVIEWED.
Strict Falsifier / Failure Trigger $\sum c_i \neq \text{score}$ or score outside declared D-band trips BAND_MISMATCH in demand.py. Generic justification text trips MISSING_DEMAND_EVIDENCE.

Stage 3 · Independent Blind QRT Adjudication

Stage 03

Assemble a sanitized, source-only packet (stripping author solutions, hints, and keys). An authorized independent expert solves the question blind, selects the primary cognitive operation, and assigns the coverage role.

Tools & Templates Used: grade9qa qrt-bind src/grade9qa/qrt_binding.py docs/agent-entry/07-independent-review.md

Measurable Pass Benchmark Primary operation must belong strictly to the 7 canonical verbs: RETRIEVE, EXPLAIN, APPLY, MODEL, REPRESENT, SYNTHESIZE, JUSTIFY. The first-pass review must be sealed with a SHA-256 digest before answer key exposure. Verified against versioned independent reviewer receipt and eligibility registry (see R2 audit templates).
Strict Falsifier / Failure Trigger Use of non-canonical verbs (e.g., CALCULATE, SOLVE), self-review by the author, or unsealed evaluations immediately fails QRT admission.

Stage 4 · Disciplinary Warrants & Topic Adapter

Stage 04

Explicitly bound every formula and physical law. Document the exact physical claim, validity domain, assumptions, exceptions, and coordinate/sign conventions. Ensure directional consistency.

Tools & Templates Used: schemas/v1/warrant.schema.json templates/physics-blueprint/physics-blueprint.D3-D4.json grade9qa subjects-audit

Measurable Pass Benchmark Every warrant must contain non-empty arrays for assumptions, validity_domain, and exceptions. Taught reasoning direction must strictly match tested task direction ($A \to B \neq B \to A$).
Strict Falsifier / Failure Trigger Reversing directional claims or omitting boundary assumptions (e.g., assuming $F = -GMm/r^2$ inside a hollow planet) trips WARRANT_DIRECTION_MISMATCH.

Stage 5 · Native Core2 Interactive Tablet Module & Learning Bridge

Stage 05

Construct the interactive, full-page student question card for 12.7-inch tablets. Structure explanations into 4 cognitive slots ($X$ Setup, $Y$ Law, $Z$ Formulation, $W$ Crux). Implement 3-tier progressive hints ($H_1, H_2, H_3$), commitment-first event handlers, interactive attempt evaluation banners, misconception retry controls, and direct learning bridge routes into Stage 6 master lessons.

Tools & Templates Used: ag-core2 skill (v4.1) per-topic HTTP Playwright QA (confirm actual path) templates/core2-exam-card/TEMPLATE-bank.json nsejs/js/core2-learning-route.js architecture/production-checklist.html

Measurable Pass Benchmark (Four Core2 pillars plus tablet ergonomics)
  • 1. Procedure: Full 3-state evaluation lifecycle: Uncommitted ➔ Committed (Feedback Banner + Badges) ⇌ [🔄 Reset & Try Again] that creates a linked revision and never deletes the first persisted attempt. Single Master Topic Navigation bar positioned directly above in-place #topicWorkspace (zero scroll-hunting; zero duplicate bars). Client-side cache busting via ?v=4.1.x on script tags and { cache: "no-store" } on dynamic JSON fetches.
  • 2. Workflow: Adversarial Jargon Filter strictly enforced: zero developer mock strings (producer proposal, differs from producer, asserted stem digest agrees with display) on student surfaces. Technical hashes and QRT formulas strictly encapsulated in a collapsed <details class="q-source-custody-drawer">.
  • 3. Self-Check: Automated Playwright assertion banning forbidden strings (regex match on /producer/i), W3C SVG XML strictness audit (zero HTML named entities like &middot;), and global repository-wide ID uniqueness check.
  • 4. Evidences: Mandatory post-commitment visual screenshot proof (playwright_evidence_qXX_[width].png) verifying banners and option badges before release, plus HTTP 200 cache-bypass network verification.
  • 5. Layout & Ergonomics: 0px horizontal scroll overflow at 1000×1600 portrait and 1600×1000 landscape, plus appropriate responsive viewports. Touch targets $\ge 48\text{px}$ (WCAG AAA). Derivations strictly inert (display: none) until commit. W3C SVG font size $\ge 14\text{px}$.
Strict Falsifier / Failure Trigger Horizontal scrollbar on any viewport, hint leaking Slot $W$, solution visible in DOM/alt text prior to commit, developer mock strings (`differs from producer proposal`, `asserted stem digest agrees with display`) visible in student UI, HTML named entities in SVGs crashing the XML parser, missing reset/retry control, or missing visual screenshot proof immediately fails Stage 5 audit.

Stage 6 · Core1A Master Lesson & Core1B Fresh Transfer

Stage 06

Author Core1A to sufficiently teach the decisive mental pivot. Author Core1B as an unseen twin problem testing the exact same reasoning signature under altered physical conditions. Tab 1 must render the complete Core 2 Reference Item with vector diagram and commitment box; never an empty disclaimer. Compile the B1–B7 witness ledger.

Tools & Templates Used: templates/skills/source-to-core1a-r2 templates/skills/source-to-core1a-r2/references/benchmarks.md docs/agent-entry/CURRENT_CONCEPT_COMPANION.md

Measurable Pass Benchmark (Non-Compensatory B1–B7 Rubric) All 7 witnesses satisfied: B1 Target (explicit demand & full Tab 1 question rendering), B2 Signature (distinctive pivot), B3 Sufficiency (Core1A teaches the crux), B4 Reconstruction (Core1B is fresh & unseen), B5 Protection (attempt secured before hints), B6 Diagnosis (diagnoses wrong models), B7 Provenance (expert physics sign-off). Tab 1 must display the complete target stem, vector SVG, and interactive options.
Strict Falsifier / Failure Trigger If Core1B only alters numbers without testing altered physical boundaries, B4 fails. Missing first-attempt enforcement fails B5. Placeholder disclaimers in Tab 1 ("source authority note") without problem statement fails B1 Target. Non-compensatory rule: failing one witness holds the entire lesson.

Stage 7 · Dual-Engine Verification & Technical Preview Gate

Stage 07

Execute automated unit test suites, headless Chromium viewport regression audits, and build pipelines. Report mechanical compliance while strictly holding academic release.

Tools & Templates Used: pytest -q tools/preview_ui_regression.py per-topic HTTP Playwright QA (confirm actual path) .github/workflows/deploy.yaml

Measurable Pass Benchmark 100% pass on pytest (schemas, DAG reference cycles, SHA hashes, global ID uniqueness, attempt evaluation suites). 100% pass on Playwright tablet regression suite (0 console errors, 0px overflow, zero XML entity errors in SVGs, 0 matches for /producer/i, verified attempt commitment & [🔄 Reset & Try Again] controls). Mandatory generation of post-commitment visual screenshots (playwright_evidence_*.png) as tangible proof of UI compliance. Status explicitly output as MECHANICAL_PASS / HOLD: ACADEMIC_ADMISSION. All question badges are derived from actual source and academic status; {Reviewed} or peer-audited wording cannot coexist with unresolved admission HOLD.
Strict Falsifier / Failure Trigger Any automated test failure, broken link, SVG XML parsing crash, forbidden developer mock string leak, missing reset control, missing visual proof screenshot, or auto-generated human approval receipt aborts publication immediately. Software passing tests must never remove Rule 13 HOLD or claim academic authority.

Stage 8 · Independent Academic Review & Delegated Batch Admission

Academic gate

Source-authenticated Core2 status, scientific accuracy, actual QRT demand and B1–B7 learning quality require independent evidence. R00 checks exact-head technical proof; a genuinely unexposed R01 independently solves and evaluates the scientific teaching and fresh transfer. The Owner approves one representative Golden exemplar and standard, not individual routine questions. Subsequent batches follow delegated, risk-based review when the policy is activated.

References: R2 Quality Contract, R00/R01/Golden/Batch receipts, actual policy status, and Independent Audit Field Guide.

Measurable source qualification and delegated review
  1. Exact source: paper, set, question, stem, options, figure and answer/key identities agree. Authored transfers remain distinct from authenticated examination questions.
  2. Independent science/QRT: R01 independently derives the physics, assesses primary operation and five demand factors, and evaluates every applicable B1–B7 witness; author labels do not confer D3/D4 acceptance.
  3. Golden approval once: a complete representative Core2 + Core1A + Core1B exemplar passes the scientific, novel-task, attempt-protection and adverse test gates. Owner approves the pinned exemplar and production standard once.
  4. Delegated continuing review: require an evidence packet per changed item, with a proposed independent minimum sample of 20% and at least one item per topic per batch. Review all new Physics laws, D4 proofs, disputed keys and defect-triggered items individually.
  5. Honest admission status: a scoped independent/delegated receipt—not an author badge or green software test—governs any academic-status promotion.
Strict falsifier / failure trigger A fabricated reviewer receipt, contradictory source identity, incorrect law, cloned transfer, leaked precommit answer or changed question with no evidence packet holds the affected scope. quality-policy.v1.json remains PILOT_AWAITING_OWNER_GOLDEN; a passing pilot is not enforced branch protection or a Golden acceptance.

The 4 Non-Bypassable Pillars of Core 2 Production (V4.1 Specification)

To permanently eliminate developer regressions, stale cache loops, and jargon leaks, every candidate question module must satisfy all four operational dimensions before delivery:

Dimension V4.0 Legacy Defect / Failure Mode V4.1 Invariant Architecture Standard
1. Procedure
Execution Steps		 • Unspecified attempt lifecycle (options locked with no result banner).
• Duplicate topic navigation bars (#topicNav vs header).
• Stale disk caching of client-side scripts. 		• Three visible states with immutable evidence: Uncommitted ➔ Committed (Feedback) ⇌ [🔄 New Linked Attempt]. Preserve first response, content digest, help exposure and timestamp on retry.
• Single Master Controller: One unified topic controller mounted immediately above in-place #topicWorkspace (zero scroll hunting).
• Cache Busting Protocol: Explicit ?v=4.1.x on all script tags and { cache: "no-store" } on dynamic JSON fetches.
2. Workflow
Boundary Gates		 • Developer mock phrases (PRODUCER-PROPOSED, DIFFERS FROM PRODUCER) leaked into student cards.
• Raw SHA-256 hash digests and QRT formulas exposed in student card headers.
• Building frontend readers before Gate 0 source sealing. 		• Adversarial Jargon Filter: Strict segregation of student UI (clean badges, official keys, clear options) from internal audit registers.
• Encapsulated Audit Drawer: All technical digests and QRT math are encapsulated inside a collapsed <details class="q-source-custody-drawer">.
• Fail-Closed Gate Hierarchy: Gate 0 (Custody) ➔ Gate 1 (QRT) ➔ Gate 2 (DOM) ➔ Gate 3 (Dual Verification).
3. Self-Check
Automated Linters		 • CI checks only verified exit_code == 0 and console_errors == 0, allowing ugly mock strings and missing retry controls to pass as "green".
• HTML named entities (&middot;) crashed Chromium XML parser unnoticed. 		• Forbidden Jargon Linter: Automated Playwright assertion regex testing body for /producer/i, /differs from producer/i, and /stem digest agrees/i (fails closed on match).
• W3C SVG XML Entity Linter: Pre-commit check forbidding HTML named entities; enforcing UTF-8 literal characters (·, →, ✕) or numeric entities (&#183;).
• Global ID Collision Linter: Enforcing 100% unique question IDs across all subjects and examination years.
4. Evidences
Tangible Proof		 • Handoffs relied solely on terminal text logs (pytest passed).
• No visual verification that the committed state or retry flow actually functioned in the browser. 		• Visual Post-Commitment Screenshots: Mandatory capture of timestamped Playwright screenshots (playwright_evidence_qXX_[width].png) visually proving feedback banner, option badges, and active reset button.
• Network Cache-Bypass Receipt: Proof of HTTP 200 responses with updated payload bytes, ensuring reviewer inspects fresh code.
• Sealed Review Manifest: SHA-256 manifest of all payload files under Rule 13 HOLD disposition.

Key Pipeline Lessons & Architecture Invariants (V4.1 Standard)

Operational Challenge V4.0 Legacy Vulnerability V4.1 Invariant Architecture Standard
Adversarial Developer Mock Strings & Jargon Defensive internal developer/mock phrases (SELECTED · DIFFERS FROM PRODUCER PROPOSAL, PRODUCER-PROPOSED, asserted stem digest agrees with display · QRT HOLD) leaked onto student question cards. Completely eradicated all "producer" and raw hash strings. Use clean status labels from actual independently qualified state; do not hardcode Reviewed or peer-audited on candidate questions, instant evaluation banners (✅ CORRECT / ❌ INCORRECT), option badges, and interactive 🔄 Reset & Try Again controls. Cryptographic digests are strictly encapsulated inside collapsed <details> drawers.
Single Master Topic Navigation Bar Two competing topic pill bars (one at top, another below for question filters) forced users to hunt and scroll, causing disorientation and mismatched topic filtering across subjects. A single unified Master Topic Navigation Bar sits directly above the question bank, bidirectionally synchronized with the search bar, filter dropdowns, and deep-dive workspaces across Physics, Chemistry, and Biology.
W3C SVG Asset Standards & XML Strictness Embedded SVG diagrams containing HTML named entities (&middot;, &rarr;, &cross;) triggered fatal XML parser errors in Chromium (Entity 'middot' not defined), causing blank diagrams on tablets. All vector assets must strictly adhere to W3C XML standards using UTF-8 literal characters (·, →, ⇒, ✕) or numeric entities (&#183;, &#8594;), with typography $\ge 14\text{px}$ and verified zero-error rendering across headless Playwright viewports.
Bit-for-Bit Stem SHA-256 Sealing & Deduplication Dummy placeholder hashes and duplicate question IDs (e.g. collisions between 2019 Optics and Electrostatics) tripped asserted stem digest CONFLICTS with display warnings and broke candidate custody. Gate 0 enforces 100% unique question IDs across all subjects and bit-for-bit SHA-256 agreement between displayed stems and declared integrity manifests (declared_matches_observed: true across 100% of candidate records).
Client-Side Cache Invalidation & Attempt Migration Tablet browsers aggressively cached JavaScript and data JSONs on disk, running stale prototype code even after repository updates were deployed. Enforce versioned query parameters (?v=4.1.5) on all script tags and { cache: "no-store" } on dynamic JSON fetches, with backward-compatible localStorage attempt migration so user attempts are preserved across updates.
Disconnected Candidate Banks Stage 5 candidate question bank was an isolated silo with no links to Stage 6 learning modules. Every candidate card and topic header features dynamic #topic-core1-ribbon and direct touch buttons bridging into 3-stage / 6-stage master lessons.
Empty Tab 1 Disclaimers Stage 6 Core 1 modules hid target problems behind legal disclaimers ("Source authority note"). Tab 1 must render the complete, self-contained reference problem statement, vector SVG diagram, and unassisted attempt commitment box across 100% of lessons.
Removing {Unvalidated} in CI Confusion over whether passing green unit tests allowed removing Rule 13 warning banners. Software CI only certifies Stage 7 mechanical compliance. Rule 13 HOLD is an immutable Stage 8 gate, strictly removable only by human academic review receipts.
12.7" Tablet Ergonomics Cramped inline anchor tags and squished topic links failed tablet touch targets. All interactive filters, buttons, and route cards strictly adhere to $\ge 48\text{px}$ touch targets, zero layout shifts, and 0px horizontal scroll overflow.
Blueprint Validation Boundaries Assuming author-proposed QRT demand scores (MODEL / D2) or green build passes constituted "Blueprint Validation". Software generation is candidate authoring only. Physics blueprint is a draft WPE pilot; Chemistry and Biology blueprints are unapproved. All items remain under fail-closed HOLD: ACADEMIC_ADMISSION until blind Stage 8 expert review.
QRT Operation & Demand Visibility QRT cognitive terms (RETRIEVE, MODEL, SYNTHESIZE) and D1–D4 Demand bands were buried in internal JSON maps, invisible on top-level cards. Every candidate card, recovery module, and lesson directory must surface high-visibility QRT Operation pills, D-Band ratings, and decisive Crux Move tags directly in the user interface.
Elimination of Internal Agent Jargon Internal multi-agent plumbing and handoff stubs (Agent A, Agent B, remain with Agent A, Core 2 status) leaked into student-facing lesson headers and tab bars. All user-facing headers, tabs, and metadata must strictly adhere to clean disciplinary standards (1. Core 2 Target Problem, Target Item • Demand Band • QRT Operation • Crux Move) with zero internal agent role terminology.
